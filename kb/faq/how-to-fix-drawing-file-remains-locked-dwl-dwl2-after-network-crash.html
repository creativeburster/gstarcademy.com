How to Fix 'Drawing File Is Currently in Use / Locked' (.DWL & .DWL2) After a Crash

Safely unlock network DWG files stuck in Read-Only mode after a workstation crash or VPN drop by inspecting and removing orphaned .dwl, .dwl2, and SMB file handles.

By GstarCAD Academy Engineering Editorial Board (Suzhou Gstarsoft Co., Ltd.) Reviewed by GstarCAD Academy Editorial Team Last reviewed 2026-11-03 Editorial Process
⚡ Quick Engineering Answer (TL;DR)

Verify via WHOHAS that no colleague actually has the drawing open, close GstarCAD on the crashed workstation, navigate to the project folder in Windows Explorer (with 'Hidden items' enabled), and delete the orphaned 1-KB .dwl and .dwl2 lock files sharing the drawing's name.

1. Root Cause & DWG Database Symptom Analysis

When a workstation opens Plan-A101.dwg on a shared SMB network drive or NAS, GstarCAD and AutoCAD automatically create two tiny hidden lock files in the same directory: Plan-A101.dwl (plain text) and Plan-A101.dwl2 (XML) containing the username, computer hostname, and timestamp. If that PC loses power or drops VPN, those lock files remain behind and force the drawing into Read-Only mode.

2. Step-by-Step Resolution in GstarCAD & AutoCAD

Step 1: Inspect Who Holds the Lock (.DWL / WHOHAS)

Enable View → Show → Hidden items in Windows File Explorer and open DrawingName.dwl in Notepad (or run WHOHAS in CAD). It displays the exact Windows username, workstation ID, and time the file was opened.

Step 2: Delete Orphaned .DWL and .DWL2 Files After Confirming Crash

Once you confirm with the colleague that their CAD session closed, select both DrawingName.dwl and DrawingName.dwl2 in Windows Explorer and press Delete.

Step 3: Clear Stuck Windows Server SMB File Handles (fsmgmt.msc)

If the `.dwl` files are gone but Windows Server still says "The action can't be completed because the file is open in another program", a dead SMB network socket is hanging on the server. Have your IT admin open Shared Folders (`fsmgmt.msc` → Open Files) on the file server, right-click the stuck `.dwg` handle, and click Close Open File.

3. System Variables & Command Diagnostic Table

4. One-Click AutoLISP Fix Script (AutoLISP Active Drawing Lock (.DWL) WhoHas Inspector)

(defun c:CHECK-DWL-OWNER ( / dwlPath fp line)
  (setq dwlPath (strcat (getvar "DWGPREFIX") (vl-filename-base (getvar "DWGNAME")) ".dwl"))
  (if (findfile dwlPath)
    (progn
      (setq fp (open dwlPath "r"))
      (princ "\n=== Active .DWL Lock File Info ===")
      (while (setq line (read-line fp)) (princ (strcat "\n  " line)))
      (close fp))
    (princ "\n[Lock Info] No .dwl file found in current directory."))
  (princ)
)

1. DWG Header & Registry Persistence Scope

Variables and object properties fall into three persistence scopes: Drawing-Saved (DXF Header) variables that travel with the .dwg file to subcontractors, Registry-Saved (Profile .arg) settings that persist per Windows workstation user, and Session-Volatile states that reset on every launch unless locked inside acaddoc.lsp. Always verify persistence scope via SYSVDLG before issuing sheets to an ISO 19650 Common Data Environment (CDE).

2. Multi-Core Regeneration & Memory Hygiene
