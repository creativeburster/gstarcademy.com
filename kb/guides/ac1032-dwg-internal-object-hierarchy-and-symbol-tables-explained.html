AC1032 DWG Internal Object Hierarchy, Symbol Tables & Dictionaries Explained

Deep architectural dive into the native AC1032 (DWG 2018–2026) database structure: the 9 fixed Symbol Tables, Named Object Dictionary (NOD), and Block Table Records.

By GstarCAD Academy Engineering Editorial Board (Suzhou Gstarsoft Co., Ltd.) Reviewed by GstarCAD Academy Editorial Team Last reviewed 2026-11-03 Editorial Process

1. Engineering Architecture & Core Methodology

A .dwg file (format version AC1032 for 2018–2026) is not a flat vector image—it is a hierarchical, pointer-linked object-oriented relational database. Understanding how GstarCAD and AutoCAD organize Symbol Tables, Block Table Records (BTRs), and the Named Object Dictionary (NOD) is essential for GRX C++ developers and CAD database recovery specialists.

2. Step-by-Step Production Workflow & Command Modules

1. The 9 Fixed Symbol Tables (AcDbSymbolTable)

Every DWG contains exactly 9 root Symbol Tables: BLOCK_RECORD (Block definitions + *Model_Space + *Paper_Space), LAYER, STYLE (Text styles), LTYPE (Linetypes), VIEW, UCS, VPORT, REGAPP (XData application IDs), and DIMSTYLE.

2. Where Graphical Entities Actually Live (*Model_Space & *Paper_Space BTRs)

Lines, circles, and dimensions do not float loose in the database; they are owned by special Block Table Records named *Model_Space and *Paper_Space (plus *Paper_Space0, etc. for each Layout tab). Inserting a block creates an AcDbBlockReference (INSERT) pointing to its parent AcDbBlockTableRecord.

3. The Named Object Dictionary (NOD) — Home of Non-Graphical Objects

Anything created after AutoCAD R13 that doesn't fit the 9 legacy Symbol Tables lives inside the tree-structured Named Object Dictionary (NOD): ACAD_GROUP, ACAD_MLINESTYLE, ACAD_LAYOUT, ACAD_PLOTSETTINGS, ACAD_SCALELIST, and ACAD_IMAGE_DICT. Orphaned entries here are the #1 cause of DWG file bloat.

4. Automation Script & Reference Implementation (AutoLISP Named Object Dictionary (NOD) Inspector & Bloat Auditor)

(defun c:INSPECT-NOD ( / nod item)
  (setq nod (namedobjdict))
  (princ "\n=== Root Named Object Dictionary (NOD) Entries ===")
  (foreach item (entget nod)
    (if (= (car item) 3)
      (princ (strcat "\n  [NOD Key] " (cdr item)))))
  (princ)
)

5. Production QA Verification & Competency Checklist

  • Use Handles (Group 5) rather than Entity Names (Group -1) when storing cross-session references, because entity names regenerate on every file open.
  • Audit the Named Object Dictionary (INSPECT-NOD) when hunting down 3rd-party plugin dictionary bloat.
  • Purge Registered Applications (-PURGE -> Regapps) regularly to keep the REGAPP symbol table clean.

Enterprise AC1032 Database Internals & Cross-Version Diagnostics

In multi-office engineering environments operating across GstarCAD 2027, GstarCAD Mechanical, GstarCAD Architecture, and legacy AutoCAD (2018–2027) seats, mastering AC1032 DWG Internal Object Hierarchy, Symbol Tables & Dictionaries Explained requires understanding how the underlying AC1032 DWG binary database serializes entity handles, symbol table records, and Named Object Dictionary (NOD) pointers.

1. DWG Header & Registry Persistence Scope

Variables and object properties fall into three persistence scopes: Drawing-Saved (DXF Header) variables that travel with the .dwg file to subcontractors, Registry-Saved (Profile .arg) settings that persist per Windows workstation user, and Session-Volatile states that reset on every launch unless locked inside acaddoc.lsp. Always verify persistence scope via SYSVDLG before issuing sheets to an ISO 19650 Common Data Environment (CDE).

2. Multi-Core Regeneration & Memory Hygiene

When processing large civil corridors, dense plant P&IDs, or 50-sheet architectural Xref trees, unpurged Registered Application IDs (REGAPP), orphaned DGN stroke dictionaries, and redundant annotation scales degrade spatial index (INDEXCTL = 3) lookup speed. Executing a pre-submittal AUDIT, command-line -PURGE → Regapps, and OVERKILL pass keeps file open times under 2 seconds on GstarCAD's multi-threaded graphics kernel.

3. Hybrid AutoCAD + GstarCAD Team Coexistence

Because GstarCAD reads and writes native AC1032 binary records without intermediate import/export translation, dynamic block grips, associative hatches, XData payloads (DXF groups 1000–1071), Paper Space viewport layer overrides (VPLAYER), and X.509 digital signatures round-trip losslessly between AutoCAD and GstarCAD seats on shared SMB/BIM cloud folders.

Production Field Verification Protocol (ISO 9001 / ISO 19650 Gate)

  1. Baseline Template Audit: Confirm that the active drawing inherits layer naming, linetype scales (PSLTSCALE = 1, MSLTSCALE = 1, LTSCALE = 1.0), and dimension styles from the enterprise .dwt / .dws standards file via CHECKSTANDARDS.
  2. Coordinate & Unit Integrity: Run -DWGUNITS or check INSUNITS, LUNITS, and MEASUREMENT to guarantee 1:1 metric (`mm`/`m`) or imperial (`in`/`ft`) block and Xref insertion scaling, with OSNAPZ = 1 preventing unintended 3D elevation drift.
  3. Submittal Packaging & Mobile Review: Lock all Paper Space viewports (`DisplayLocked = Yes`), bind or relative-path all external references via ETRANSMIT, and verify final plotted PDF/A lineweights (`ISO full bleed`) alongside DWG FastView mobile cloud markup links.
