Course 20: Enterprise CAD Administration — Silent MSI Deployment, GstarLM Network Licensing & QA Audits

Roll out GstarCAD 2027 across 500+ workstations via Active Directory GPO/SCCM silent MSI flags, configure redundant GstarLM license servers, and enforce automated pre-transmittal DWG audits.

Course Technical Scope & Production Competencies

Deploying and governing 500+ CAD seats across multi-site engineering offices requires automated software packaging, high-availability license server clustering, and centralized path locking. This capstone course equips IT directors and CAD Managers to administer GstarCAD 2027 at enterprise scale.

  • Execute zero-touch silent MSI installations (msiexec /i GstarCAD2027.msi /qn) via Microsoft Intune, SCCM, or Active Directory GPO with pre-bound network license server IPs.
  • Deploy and monitor the GstarLM Network License Manager across Windows or Linux servers, configuring firewall ports, subnet access rules, and offline laptop license borrowing.
  • Lock corporate support file search paths, printer config directories (.pc3/.ctb), .dws CAD standards, and TRUSTEDPATHS via centralized Windows Registry profiles and gcaddoc.lsp startup scripts.

Module 1: Enterprise CAD Administration: Silent MSI Rollout, GstarLM Floating Licenses & Security Governance

Unlike cloud-only subscription CAD platforms that force every engineer to authenticate against external vendor servers and prohibit floating seat sharing, GstarLM (Gstarsoft License Manager) operates 100% inside your corporate intranet (including completely air-gapped defense, semiconductor, and power-grid networks). A central pool of 200 floating perpetual licenses can dynamically serve 450 engineers working across staggered shifts or multiple global time zones.

Through a master `gcaddoc.lsp` script hosted on a read-only network share and added to `TRUSTEDPATHS`, CAD Managers automatically enforce corporate `PSLTSCALE`, `INDEXCTL`, `XLOADCTL`, and `.ctb` plot table paths every time any engineer opens a drawing.

Module 2: Step-by-Step Hands-On Command Execution Lab

Follow this structured 4-step laboratory procedure directly at the GstarCAD command line or dynamic input prompt:

  1. Step 1 — Environment & System Variable Initialization: At the command prompt, verify the active state of core commands and variables: msiexec /qn, GstarLM License Manager, OPTIONS Profiles (.arg), -PURGE, AUDIT. Ensure that object snap bitcodes (OSMODE=175), associative dimensioning (DIMASSOC=2), and multi-core display regeneration (WHIPTHREAD=3) are active.
  2. Step 2 — Primary Geometry & Metadata Authoring: Execute the primary workflow on standardized ISO 13567 or discipline-specific layers. Never place production geometry or block definitions on Defpoints, and keep internal block geometry on Layer 0 so instances inherit host layer properties dynamically.
  3. Step 3 — Associative Verification & Revision Auditing: Test parametric associativity by stretching or modifying parent geometry and confirming that linked dimensions, attributes, schedules, or section views update automatically without disassociation warnings (ANNOMONITOR=2).
  4. Step 4 — Pre-Transmittal Quality Assurance (QA/QC): Prior to saving or publishing the deliverable, run OVERKILL to eliminate duplicate vectors, -PURGE (RegApps and All) to strip orphaned symbol table bloat, and AUDIT to verify 100% AcDbObject handle integrity.
