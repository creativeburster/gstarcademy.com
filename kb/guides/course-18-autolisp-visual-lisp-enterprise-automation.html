Course Technical Scope & Production Competencies

Any drafting task repeated more than five times a week should be automated in code. Because GstarCAD 2027 includes a 100% compatible AutoLISP, Visual LISP (`vl-*`, `vla-*`, `vlax-*`), and DCL dialog engine, engineers can write or migrate automation scripts that manipulate the DWG database at 50x the speed of manual drafting.

  • Master DXF Group Code entity association lists (0=Entity Type, 8=Layer, 10=Start Point, 40=Radius, 62=Color) using (ssget), (entget), (subst), (entmod), and high-speed (entmakex).
  • Leverage ActiveX COM object methods via (vl-load-com) and (vla-*) to manipulate dynamic block properties, layouts, layers, and external Excel workbooks.
  • Wrap production routines in defensive error-handling frameworks (*error*, vla-StartUndoMark, CMDECHO=0, OSMODE restoration) so cancelled commands never corrupt user system variables.

Module 1: Production AutoLISP & Visual LISP Programming: DXF Group Codes, entmakex & COM Automation

Understanding the performance hierarchy of AutoLISP in GstarCAD 2027 separates amateur macro writers from enterprise CAD programmers. Calling (command "_LINE" pt1 pt2 "") forces the CAD engine to invoke the interactive command-line parser, evaluate running Object Snaps (`OSMODE`), and trigger screen redraws on every iteration. Conversely, calling (entmakex (list (cons 0 "LINE") (cons 8 "0") (cons 10 pt1) (cons 11 pt2))) appends the C++ `AcDbLine` struct directly into the active `BlockTableRecord` in memory—generating 10,000 entities in under 0.15 seconds.

Moreover, always zero out `OSMODE` (or set bit `16384`) inside any script that must use `(command ...)`, otherwise an active Endpoint snap on screen will hijack the programmatic coordinate points!

Module 2: Step-by-Step Hands-On Command Execution Lab

Follow this structured 4-step laboratory procedure directly at the GstarCAD command line or dynamic input prompt:

  1. Step 1 — Environment & System Variable Initialization: At the command prompt, verify the active state of core commands and variables: APPLOAD, VLIDE, ssget, entget, entmod, vlax-ename->vla-object, *error*. Ensure that object snap bitcodes (OSMODE=175), associative dimensioning (DIMASSOC=2), and multi-core display regeneration (WHIPTHREAD=3) are active.
  2. Step 2 — Primary Geometry & Metadata Authoring: Execute the primary workflow on standardized ISO 13567 or discipline-specific layers. Never place production geometry or block definitions on Defpoints, and keep internal block geometry on Layer 0 so instances inherit host layer properties dynamically.
  3. Step 3 — Associative Verification & Revision Auditing: Test parametric associativity by stretching or modifying parent geometry and confirming that linked dimensions, attributes, schedules, or section views update automatically without disassociation warnings (ANNOMONITOR=2).
  4. Step 4 — Pre-Transmittal Quality Assurance (QA/QC): Prior to saving or publishing the deliverable, run OVERKILL to eliminate duplicate vectors, -PURGE (RegApps and All) to strip orphaned symbol table bloat, and AUDIT to verify 100% AcDbObject handle integrity.
