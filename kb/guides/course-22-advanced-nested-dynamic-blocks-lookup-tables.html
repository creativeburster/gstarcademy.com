Course 22: Advanced Nested Dynamic Blocks, Double-Lookup Tables & Chained Actions

Engineer advanced GstarCAD 2027 Dynamic Blocks with chained stretch/array actions, double-lookup tricks, and Block Properties Tables for multi-state equipment catalogs.

By GstarCAD Academy Engineering Editorial Board (Suzhou Gstarsoft Co., Ltd.) Reviewed by Zhang Mingyuan, B.Eng. (Distinguished DWG Graphics Kernel & GRX SDK Architect) Last reviewed 2026-11-03 Editorial Process & Testbed

1. Engineering Architecture & Core Methodology

While basic Dynamic Blocks use a single Visibility State or Linear Stretch grip, enterprise engineering libraries require **Chained Parameter Actions** and **Multi-Parameter Lookup Tables (`AcDbBlockPropertiesTable`)**. For example, when an electrical engineer stretches a DIN mounting rail in GstarCAD 2027, terminal blocks should array automatically at `6.2 mm` pitch, the center mounting slot should remain centered (`0.5x` distance multiplier), and the part number attribute should update automatically via a Lookup Table.

2. Step-by-Step Production Workflow & Command Modules

Module 1: Distance Multipliers (0.5x Symmetry) & Offset Angles

To keep a center stiffener rib or bolt hole centered while stretching only the right-hand grip of a steel beam, attach a **second `Stretch Action`** to the same `Linear Parameter`, select the center rib geometry, and set its **Distance Multiplier = `0.50`** in the Properties palette (`Ctrl+1`).

Module 2: Chaining Parameters (`Chain Actions = Yes`)

When Parameter A's action needs to trigger Parameter B's action (for example, a Lookup Table changes `Distance1`, which in turn must trigger an `Array Action` tied to `Distance1`), select the driven parameter in `BEDIT`, open `Ctrl+1`, set **Chain Actions = Yes**, and include the driven parameter inside the driving action's selection set.

Module 3: Combining Visibility States with Lookup Tables (Double-Lookup Pattern)

Because standard CAD blocks allow only one native `Visibility Parameter` per block definition, you can synchronize multiple geometric states with parametric dimensions by wiring both `Linear/Point Parameters` and `Visibility1` columns into a single **Block Properties Table (`BPT`)**.

3. Command, Variable & Standard Reference Matrix

Command / Parameter Scope / Target Engineering Behavior & Best Practice
BPARAMETER > Linear / Polar Value Set: Increment / List Restricts stretch grips to standard catalog sizes (e.g., 100mm step increments).
BACTIONBARMODE = 0 or 1 Block Editor UI Set to 0 to display classic action lightning bolts so selection sets are easy to audit.
ATTSYNC & BATTMAN Attribute Governance Ensure all ATTDEFs inside Dynamic Blocks have 'Lock Position = Yes' enabled.
RESETBLOCK Instance Recovery Restores selected dynamic block insertions back to their default catalog state.

4. Automation Script & Reference Implementation (Dynamic Block Property Inspector LISP)

(defun C:INSPECTDYNBLK ( / ent obj props p)
  (vl-load-com)
  (if (and (setq ent (car (entsel "\nSelect a Dynamic Block insertion: ")))
           (= (vla-get-ObjectName (setq obj (vlax-ename->vla-object ent))) "AcDbBlockReference")
           (= (vla-get-IsDynamicBlock obj) :vlax-true))
    (progn
      (princ (strcat "\nEffective Block Name: " (vla-get-EffectiveName obj)))
      (setq props (vlax-variant-value (vla-GetDynamicBlockProperties obj)))
      (foreach p (vlax-safearray->list props)
        (princ (strcat "\n  Param [" (vla-get-PropertyName p) "] = "
                       (vl-princ-to-string (vlax-variant-value (vla-get-Value p)))))
      )
    )
    (princ "\nSelected object is not a Dynamic Block.")
  )
  (princ)
)

5. Production QA Verification & Competency Checklist

  • Confirm every `ATTDEF` targeted by a Move, Stretch, or Flip action has `Lock Position = Yes` enabled in `Ctrl+1`.
  • Test `RESETBLOCK` and `DATAEXTRACTION` on 5 stretched instances to verify `EffectiveName` remains unified rather than splitting by `*U###` anonymous handle.
  • Set `Show Properties = No` on internal helper parameters so users only see clean catalog inputs in `Ctrl+1`.
