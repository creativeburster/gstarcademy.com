Course 05: Multi-Scale Annotative Dimensions, Paper Space Viewports, CTB/STB & Batch Sheet Set Publishing

Standardize multi-scale detailing across 1:20 and 1:100 viewports using CANNOSCALE, LTSCALE/PSLTSCALE/MSLTSCALE=1, monochrome CTB pen tables, Sheet Set Manager (SSM), and ETRANSMIT.

By GstarCAD Academy Engineering Editorial Board (Suzhou Gstarsoft Co., Ltd.) Reviewed by GstarCAD Academy Editorial Team Key Commands: DIMASSOC=2, ANNOALLVISIBLE=0, PSLTSCALE=1, PAGESETUP, PUBLISH, ETRANSMIT Last reviewed 2026-10-19 Editorial Process

Course Technical Scope & Production Competencies

Manual text-height multiplication—where drafters create separate 'TEXT-1-50', 'TEXT-1-100', and 'TEXT-1-200' layers and duplicate dimensions for enlarged detail callouts—is the primary source of dimension discrepancies on construction sites. Annotative Scaling in GstarCAD 2027 binds multiple paper-space scale representations directly to a single model-space annotation entity.

  • Calculate and assign exact Paper Space viewport scales (1:10, 1:50, 1:100, 1/4"=1'-0") and lock viewport camera matrices (MVIEW -> Lock = ON) to prevent accidental zoom drift.
  • Configure Annotative Text, Dimensions, Multileaders, and Hatches with ANNOAUTOSCALE = -4 and ANNOALLVISIBLE = 0 so annotations dynamically resize to 2.5mm or 3.5mm paper height in every viewport.
  • Orchestrate 200-sheet project deliverables using the Sheet Set Manager (SSM / .dst), dynamic sheet title fields (FIELD), and background multi-sheet PDF plotting (PUBLISH / BACKGROUNDPLOT).

Module 1: Annotative Object Scale Dictionaries, Paper Space Viewports & Sheet Set Publishing

Under the hood, an annotative entity in GstarCAD attaches an AcDbAnnotScaleObjectContextData dictionary entry for each supported viewport scale (e.g., 1:50 and 1:200). When a Paper Space viewport (`AcDbViewport`) is set to `1:50` (`CANNOSCALE`), the graphics pipeline queries the context dictionary and scales the glyph bounding box by $50 \times 2.5\,\text{mm} = 125\,\text{mm}$ in model units while hiding annotations that lack the `1:50` context key (`ANNOALLVISIBLE = 0`).

To ensure dashed hidden lines and centerlines render identically in both Model Space and multi-scale Paper Space viewports, engineers enforce the universal four-variable linetype equation: LTSCALE = 1.0, PSLTSCALE = 1, MSLTSCALE = 1, and CELTSCALE = 1.0.

Module 2: Step-by-Step Hands-On Command Execution Lab

Follow this structured 4-step laboratory procedure directly at the GstarCAD command line or dynamic input prompt:

  1. Step 1 — Environment & System Variable Initialization: At the command prompt, verify the active state of core commands and variables: DIMASSOC=2, ANNOALLVISIBLE=0, PSLTSCALE=1, PAGESETUP, PUBLISH, ETRANSMIT. Ensure that object snap bitcodes (OSMODE=175), associative dimensioning (DIMASSOC=2), and multi-core display regeneration (WHIPTHREAD=3) are active.
  2. Step 2 — Primary Geometry & Metadata Authoring: Execute the primary workflow on standardized ISO 13567 or discipline-specific layers. Never place production geometry or block definitions on Defpoints, and keep internal block geometry on Layer 0 so instances inherit host layer properties dynamically.
  3. Step 3 — Associative Verification & Revision Auditing: Test parametric associativity by stretching or modifying parent geometry and confirming that linked dimensions, attributes, schedules, or section views update automatically without disassociation warnings (ANNOMONITOR=2).
  4. Step 4 — Pre-Transmittal Quality Assurance (QA/QC): Prior to saving or publishing the deliverable, run OVERKILL to eliminate duplicate vectors, -PURGE (RegApps and All) to strip orphaned symbol table bloat, and AUDIT to verify 100% AcDbObject handle integrity.
