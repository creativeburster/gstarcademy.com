Course 10: Engineering Change Orders (ECO) — DWGCOMPARE, GRAPHICCOMPARE & PLM QR Code Title Blocks

Audit mechanical assembly revisions using geometric DWGCOMPARE and pixel-level GRAPHICCOMPARE, and embed ISO 18004 QR codes and Code-128 barcodes into shop drawings for ERP/PLM tracking.

By GstarCAD Academy Engineering Editorial Board (Suzhou Gstarsoft Co., Ltd.) Reviewed by GstarCAD Academy Editorial Team Key Commands: DWGCOMPARE, GRAPHICCOMPARE, QRCODE, BARCODE, FIELD Last reviewed 2026-10-19 Editorial Process & Testbed

Course Technical Scope & Production Competencies

When an external subcontractor returns a revised DWG drawing without redline clouds, manually hunting for a shifted 2mm mounting hole or a modified tolerance note across a complex A0 sheet is a severe quality hazard. Course 10 covers GstarCAD 2027's dual comparison engines and automated 2D barcode/QR-code shop-floor tracking.

  • Execute DWGCOMPARE to perform an entity-handle and geometric hash diff between two DWG revisions, highlighting additions in green, deletions in red, and unchanged geometry in gray with automated revision clouds.
  • Run GRAPHICCOMPARE to perform a sub-pixel raster overlay comparison when entity handles have been regenerated or when comparing flattened blocks and imported vector PDFs.
  • Generate ISO/IEC 18004 QR codes (QRCODE) and Code-128/EAN barcodes (BARCODE) linked to dynamic drawing properties so shop-floor optical scanners pull live PLM/ERP revision status instantly.

Module 1: Binary Vector DWGCOMPARE, Pixel-Level GRAPHICCOMPARE & QR-Code PLM Shop Tracking

GstarCAD 2027 provides two complementary visual diff engines tailored to different engineering scenarios. DWGCOMPARE operates at the database entity level: it traverses the ModelSpace block table record of Revision A and Revision B, comparing geometric coordinates, layer assignments, and text strings, and wraps every delta inside parametric revision clouds (`REVCLOUD`) that can be imported into the active drawing.

Conversely, when comparing drawings exported from two different 3D CAD systems where all entity handles and block structures differ even though the visual geometry looks identical, GRAPHICCOMPARE rasterizes both viewports into high-resolution bitmaps and performs a bitwise XOR pixel comparison—instantly exposing even a 0.5mm line shift.

Module 2: Step-by-Step Hands-On Command Execution Lab

Follow this structured 4-step laboratory procedure directly at the GstarCAD command line or dynamic input prompt:

  1. Step 1 — Environment & System Variable Initialization: At the command prompt, verify the active state of core commands and variables: DWGCOMPARE, GRAPHICCOMPARE, QRCODE, BARCODE, FIELD. Ensure that object snap bitcodes (OSMODE=175), associative dimensioning (DIMASSOC=2), and multi-core display regeneration (WHIPTHREAD=3) are active.
  2. Step 2 — Primary Geometry & Metadata Authoring: Execute the primary workflow on standardized ISO 13567 or discipline-specific layers. Never place production geometry or block definitions on Defpoints, and keep internal block geometry on Layer 0 so instances inherit host layer properties dynamically.
  3. Step 3 — Associative Verification & Revision Auditing: Test parametric associativity by stretching or modifying parent geometry and confirming that linked dimensions, attributes, schedules, or section views update automatically without disassociation warnings (ANNOMONITOR=2).
  4. Step 4 — Pre-Transmittal Quality Assurance (QA/QC): Prior to saving or publishing the deliverable, run OVERKILL to eliminate duplicate vectors, -PURGE (RegApps and All) to strip orphaned symbol table bloat, and AUDIT to verify 100% AcDbObject handle integrity.
