Porting ObjectARX C++ Plugins to GstarCAD GRX Migration Guide

Comprehensive engineering guide for ISVs and enterprise developers porting legacy AutoCAD ObjectARX codebases to GstarCAD GRX: header redirection, namespace mapping, and ABI alignment.

By Gstarcademy Editorial Team Updated 2026-09-30 Editorial process

1. High Source-Level Compatibility by Design

For independent software vendors (ISVs) with enterprise C++ plugins developed over decades, rewriting applications for alternative CAD platforms would be cost-prohibitive. GstarCAD engineered the GRX SDK specifically to maintain source-level parity with ObjectARX. More than 90% of standard ObjectARX APIs map 1-to-1 with identical class interfaces, member methods, and return values.

2. Automated Prefix & Namespace Mapping Table

The fundamental step in migrating C++ code involves updating class and function prefixes from the Autodesk convention (Ac*) to the GstarCAD convention (Gc*):

Domain ObjectARX Identifier GstarCAD GRX Identifier Notes
Core Database AcDbDatabase, AcDbEntity GcDbDatabase, GcDbEntity Identical inheritance hierarchy
Editor / Command acedRegCmds, acedPrint gcedRegCmds, gcedPrint Command stack interaction
Geometry Kernel AcGePoint3d, AcGeMatrix3d GcGePoint3d, GcGeMatrix3d Full 3D matrix math parity
Entrypoint acrxEntryPoint gcrxEntryPoint DLL initialization entrypoint

3. Single Codebase Architecture Using Preprocessor Macros

To avoid maintaining two separate codebases, implement a conditional wrapper header (e.g., CadPlatform.h):

#pragma once

#if defined(_GRX_BUILD)
    #include "gcad.h"
    #include "gcdb.h"
    #include "gced.h"
    #define CadDbDatabase   GcDbDatabase
    #define CadDbEntity     GcDbEntity
    #define CadGePoint3d    GcGePoint3d
    #define cadPrint        gcedPrint
#elif defined(_ARX_BUILD)
    #include "arxHeaders.h"
    #define CadDbDatabase   AcDbDatabase
    #define CadDbEntity     AcDbEntity
    #define CadGePoint3d    AcGePoint3d
    #define cadPrint        acedPrint
#endif

This allows your team to compile for both AutoCAD and GstarCAD from identical C++ business logic by simply switching build configurations in Visual Studio.
