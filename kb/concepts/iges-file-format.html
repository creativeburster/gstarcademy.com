IGES File Format

The IGES (Initial Graphics Exchange Specification) legacy neutral format for 2D/3D CAD data exchange.

By Gstarcademy Editorial Team Updated 2026-07-28 Editorial process

Definition & Context

IGES (Initial Graphics Exchange Specification) is a vendor-neutral file format for exchanging CAD geometry between different systems. It predates STEP and is now considered legacy, but is still encountered with older data or tools that export nothing else. IGES carries wireframe, trimmed NURBS surfaces, and — through manifold B-Rep entities — limited solid data.

Because IGES stores geometry only (no features, history, materials, or assembly structure), an IGES import arrives as static “dumb” surfaces or bodies. Virtually every CAD system (SOLIDWORKS, NX, CATIA, Inventor, Rhino, Fusion) reads and writes it through its import/export dialog, where you choose to bring data in as solids, surfaces, or curves and set a stitching tolerance.

Why It Matters

IGES matters mainly as a fallback: when a supplier or legacy system can only provide IGES, knowing its limits (surface gaps, dropped solids, no PMI) tells you what repair to expect after import. For new work, STEP AP242 is almost always the better neutral choice.

Knowing when not to use IGES is as important as knowing how — for solid exchange it frequently drops features and leaves un-stitched surfaces that must be healed before downstream CAM or analysis.

Best Practices

  • Prefer STEP AP242 for new solid/PMI exchange; reserve IGES for tools that support nothing else
  • On export, use trimmed-surface representation and set the tolerance to match the receiving system
  • On import, enable stitch / “try forming solid” and check for naked edges before modeling on the result
  • Send units and tolerance alongside the file, since IGES carries no reliable metadata

Common Pitfalls

  • Expecting solids to survive — IGES often imports as disconnected surfaces that need stitching
  • Unit mismatches (mm vs inch) silently scaling the model; confirm units on both ends
  • Tolerance too loose leaves boundary gaps; too tight bloats the file and slows import
  • Assuming features or parameters transfer — they do not; the import is static geometry
