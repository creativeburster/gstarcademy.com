BIM Collaboration Format (BCF 3.0)

An open standard XML and RESTful API protocol for communicating model issues, clash detection reports, and 3D camera viewpoints without exchanging heavy CAD files.

By GstarCAD Academy Engineering Editorial Board (Suzhou Gstarsoft Co., Ltd.) Reviewed by Dr. Lin Wei, Ph.D., PE (Chief BIM & OpenBIM Interoperability Architect) Last reviewed 2026-09-30 Editorial Process & Testbed

1. Definition & Engineering Significance

BCF 3.0 standardizes issue management across disparate platforms. Instead of emailing 500MB model files, coordinators transmit lightweight BCF topics containing GUIDs of clashing components, snapshot annotations, approval states, and 3D camera frustum coordinates.

2. Key Technical Characteristics & Rules

  • Camera Viewpoint Reproduction: Recreates exact 3D camera perspective, orthographic bounds, and section cut planes inside any recipient viewer.
  • Component Visibility & Selection: Highlights conflicting elements while ghosting or hiding surrounding non-relevant geometry.
  • Cloud Sync API: Direct bidirectional synchronization with platforms like BIMcollab, Revizto, and Solibri.

3. OpenBIM Coordination & REST API Integration

BCF (BIM Collaboration Format) 3.0 replaces unwieldy static PDF clash dossiers with lightweight XML/JSON issue payloads. Key technical mechanisms include:

  • Orthogonal & Perspective Viewpoint Cameras: Captures exact focal position, target direction, up-vector, and field of view, enabling any connected authoring software to reproduce the exact designer viewpoint with one click.
  • Component GUID Identification: Issues record specific IfcGuid references for colliding or queried elements, automatically isolating and highlighting target geometry in Revit, GstarCAD Architecture, or ArchiCAD.
  • RESTful Cloud Synchronization: BCF-API enables real-time synchronization between coordination platforms (e.g., BIMcollab, Revizto) and desktop CAD/BIM tools.

4. Project Governance & Status Lifecycle

Effective BCF governance enforces structured status progressions: Open → In Progress → Resolved → Verified → Closed. Coordination managers must prevent subcontractors from marking issues as 'Closed' without attaching an updated BCF viewpoint demonstrating clearance. Maintaining strict topic typing (Clash, Inquiry, Request for Information) keeps team task backlogs organized throughout project construction phases.
