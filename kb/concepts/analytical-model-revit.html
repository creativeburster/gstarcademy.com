Analytical Model

Revit's analytical model for structural analysis export — nodes, members, loads, and boundary conditions linked to physical elements.

By GstarCAD Academy Engineering Editorial Board (Suzhou Gstarsoft Co., Ltd.) Reviewed by Dr. Lin Wei, Ph.D., PE (Chief BIM & OpenBIM Interoperability Architect) Last reviewed 2026-07-28 Editorial Process & Testbed

Definition & Context

Revit's analytical model is a simplified geometric representation of structural elements used for export to analysis software (Robot Structural Analysis, ETABS, SAP2000, RISA). Physical columns become centerline stick elements; walls become shell elements; floors become plate elements. The analytical model carries load cases, boundary conditions (fixed, pinned, roller), member releases, and cross-section properties.

Key workflow: enable Analytical Model visibility in View Visibility Graphics > Analytical Model Categories. Adjust analytical representations using the Analytical Adjust tool to fix misaligned nodes, ensure member connectivity, and verify support conditions. The Analytical Consistency Check identifies disconnected members and unsupported nodes.

Export paths: direct link to Robot Structural Analysis Professional (bi-directional), or generic export via IFC Structural Analysis View, CIS/2 (steel), or third-party plugins (ETABS Link, RISA Link). Revit 2024+ includes the new Analytical Model category with explicit node/member management.

Why It Matters

The analytical model is the bridge between Revit's physical BIM and structural analysis packages (Robot, ETABS, SAP2000, RISA), so its quality decides whether an analysis run is meaningful. Centerline stick, shell, and plate idealisations must line up and connect correctly, or the solver sees a disconnected or mis-supported structure.

Because loads, releases, and boundary conditions live on this model, keeping it consistent with the physical geometry is what lets engineers iterate between design and analysis without re-modelling the frame each time.

Best Practices

  • Run Analytical Consistency Check before every export to identify disconnected nodes and unsupported members
  • Adjust analytical alignment so beam endpoints meet column centerlines precisely — 1mm gaps cause disconnected models in FEA
  • Define load cases (dead, live, wind, seismic) and load combinations within Revit before transferring to analysis software
  • Use analytical links (Robot, ETABS) for bi-directional workflows: analyze → resize members → update back to physical model
  • Set correct boundary conditions at foundations (fixed) and expansion joints (roller) to reflect real structural behavior

Common Pitfalls

  • Physical model modifications don't always propagate to analytical model — re-check analytical alignment after major edits
  • Curved beams have no analytical equivalent in most FEA links — they export as chord-approximated segments or are skipped
  • Load path discontinuities (floating beams, columns not reaching foundations) pass silently in Revit but cause solver failures in FEA
  • Exporting to Robot without checking unit consistency between Revit's project units and Robot's model units

Enterprise Production Implementation & GstarCAD 2027 Workflow

In industrial engineering production, mastering Analytical Model is essential for maintaining strict drawing database hygiene, geometric precision, and cross-disciplinary interoperability across DWG, BIM (IFC 4.3), and mechanical (STEP AP242 / ASME Y14.5) deliverables. When implementing this concept within GstarCAD 2027 Professional, GstarCAD Mechanical, or heterogeneous multi-CAD environments, engineering teams should adhere to the following standardized verification protocol:

  • Database Serialization & Binary Fidelity: Ensure all entities and symbol table records associated with Analytical Model are authored on standardized ISO 13567 layers rather than Layer 0 or Defpoints, and verify lossless round-trip persistence in native DWG (AC1032) format.
  • System Variable & Template Standardization: Embed pre-validated dimension styles, annotative scale lists (SCALELISTEDIT), and plotting configurations directly into your corporate .dwt seed templates so drafters never configure parameters manually from scratch.
  • Multi-Core Performance & QA Auditing: Prior to issuing construction or fabrication transmittals (ETRANSMIT), execute automated geometry audits (OVERKILL to eliminate duplicate overlapping segments, AUDIT to verify object handles, and -PURGE to strip orphaned registered applications).
Implementation Stage GstarCAD / AutoCAD Execution Quality Assurance (QA/QC) Gate
1. Environment Setup Load corporate .dwt template; verify INSUNITS and LUNITS. Confirm 1:1 metric (mm) or imperial unit consistency across all linked Xrefs.
2. Geometry & Metadata Authoring Apply associative constraints, block attributes, or GD&T tolerance frames. Verify zero disassociated annotations via ANNOMONITOR = 2.
3. Deliverable Exchange Publish via Sheet Set Manager (SSM) or export to DWG / IFC / STEP. Inspect output in DWG FastView or FastView 3D before client release.
