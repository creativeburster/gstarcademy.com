ACIS Geometry Kernel

The ACIS (SAT/SAB) 3D modeling kernel used by AutoCAD, BricsCAD, SpaceClaim, and other CAD platforms.

By GstarCAD Academy Engineering Editorial Board (Suzhou Gstarsoft Co., Ltd.) Reviewed by Zhang Mingyuan, B.Eng. (Distinguished DWG Graphics Kernel & GRX SDK Architect) Last reviewed 2026-07-28 Editorial Process & Testbed

Definition & Context

ACIS (originally Alan, Charles, Ian's System) is a geometric modeling kernel developed by Spatial (Dassault Systèmes subsidiary) that provides B-Rep (boundary representation) solid modeling capabilities to host CAD applications. AutoCAD, BricsCAD, SpaceClaim, and approximately 50 other products embed ACIS for solid/surface operations.

The kernel supports: precise NURBS surfaces, analytic surfaces (planes, cylinders, cones, spheres, tori), Boolean operations, blending (fillets/chamfers), sweeps, lofts, shelling, and topology queries. Data is serialized in SAT (text) or SAB (binary) file formats. AutoCAD's ACISOUT/ACISIN commands export/import native kernel data.

ACIS differs from Parasolid (used by SOLIDWORKS, NX) in its tolerance handling, healing algorithms, and surface intersection strategies. Translation between ACIS-based and Parasolid-based CAD often introduces tiny geometric mismatches at surface boundaries requiring healing operations.

Why It Matters

Because ACIS underpins solid modeling in AutoCAD, BricsCAD, SpaceClaim, and dozens of other products, knowing how it behaves explains why some geometry survives a round-trip and some does not. When a model moves between an ACIS host and a Parasolid host (SOLIDWORKS, NX), differences in tolerance and surface-intersection handling are what produce slivers, gaps, and failed Booleans.

Understanding the kernel helps you pick the right exchange path — a neutral STEP export usually travels better than a raw SAT hand-off between different kernels — and lets you heal problems at their source (stitching, tolerance) instead of patching symptoms downstream.

Best Practices

  • Use SAT format (text-based) for debugging geometry issues — open in any text editor to inspect entity topology
  • When exchanging between ACIS and Parasolid hosts, export via STEP AP214 to minimize kernel translation artifacts
  • Set appropriate tolerance values (typically 1e-6 for mechanical, 1e-4 for architectural) before Boolean operations
  • Validate solid topology after complex Boolean chains with CHECKSOLID or equivalent host commands
  • Prefer the binary SAB format for production file exchange — 3-5x smaller than SAT with faster parsing

Common Pitfalls

  • ACIS version mismatches cause import failures — older hosts cannot read SAT files written by newer kernel versions
  • Slivers and micro-edges from imprecise Boolean operations accumulate and eventually crash downstream operations
  • ACIS does not natively support mesh/facet bodies — importing STL into ACIS-based CAD requires conversion to B-Rep
  • Stitching open surfaces into solids fails when edge gaps exceed the session tolerance — increase tolerance or heal edges first

Enterprise Production Implementation & GstarCAD 2027 Workflow

In industrial engineering production, mastering ACIS Geometry Kernel is essential for maintaining strict drawing database hygiene, geometric precision, and cross-disciplinary interoperability across DWG, BIM (IFC 4.3), and mechanical (STEP AP242 / ASME Y14.5) deliverables. When implementing this concept within GstarCAD 2027 Professional, GstarCAD Mechanical, or heterogeneous multi-CAD environments, engineering teams should adhere to the following standardized verification protocol:

  • Database Serialization & Binary Fidelity: Ensure all entities and symbol table records associated with ACIS Geometry Kernel are authored on standardized ISO 13567 layers rather than Layer 0 or Defpoints, and verify lossless round-trip persistence in native DWG (AC1032) format.
  • System Variable & Template Standardization: Embed pre-validated dimension styles, annotative scale lists (SCALELISTEDIT), and plotting configurations directly into your corporate .dwt seed templates so drafters never configure parameters manually from scratch.
  • Multi-Core Performance & QA Auditing: Prior to issuing construction or fabrication transmittals (ETRANSMIT), execute automated geometry audits (OVERKILL to eliminate duplicate overlapping segments, AUDIT to verify object handles, and -PURGE to strip orphaned registered applications).
Implementation Stage GstarCAD / AutoCAD Execution Quality Assurance (QA/QC) Gate
1. Environment Setup Load corporate .dwt template; verify INSUNITS and LUNITS. Confirm 1:1 metric (mm) or imperial unit consistency across all linked Xrefs.
2. Geometry & Metadata Authoring Apply associative constraints, block attributes, or GD&T tolerance frames. Verify zero disassociated annotations via ANNOMONITOR = 2.
3. Deliverable Exchange Publish via Sheet Set Manager (SSM) or export to DWG / IFC / STEP. Inspect output in DWG FastView or FastView 3D before client release.
