Performance & Memory Optimization

GstarCAD's performance advantages: low memory footprint, fast file loading, and large-drawing optimization techniques.

By Gstarcademy Editorial Team Updated 2026-07-28 Editorial process

Definition & Context

This topic covers keeping GstarCAD responsive on large drawings: purging unused objects (PURGE), auditing and recovering files (AUDIT/RECOVER), controlling display and regeneration, and managing external references and heavy raster/PDF content so files open and pan/zoom quickly.

It also reflects GstarCAD's generally light memory footprint and fast file open, plus DWG housekeeping practices shared with other AutoCAD-compatible editors.

Why It Matters

On big infrastructure/architecture DWGs, performance directly affects productivity; disciplined purging and xref management prevent the slowdowns and bloat that stall a team.

Regular AUDIT/RECOVER also heads off file corruption before it causes lost work.

Best Practices

  • PURGE unused layers/blocks/styles and run AUDIT regularly to keep files lean and healthy
  • Manage xrefs (unload when not needed) and avoid embedding heavy raster/PDF unnecessarily
  • Control display density and regeneration on large drawings
  • Split oversized drawings and use xrefs instead of one monolithic file

Common Pitfalls

  • Never purging, so files accumulate bloat and slow down
  • Over-referencing heavy images/PDFs that drag performance
  • Ignoring AUDIT warnings until the file corrupts
