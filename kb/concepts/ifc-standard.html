IFC (Industry Foundation Classes)

The IFC open standard (ISO 16739) for BIM data exchange, enabling interoperability between different building design platforms.

By GstarCAD Academy Engineering Editorial Board (Suzhou Gstarsoft Co., Ltd.) Reviewed by GstarCAD Academy Editorial Team Last reviewed 2026-07-28 Editorial Process & Testbed

Definition & Context

IFC (Industry Foundation Classes, ISO 16739) is the open international standard for describing building and construction data. Unlike DWG or RVT, IFC is vendor-neutral — any BIM software can import and export IFC files for cross-platform coordination. The standard defines entity types (IfcWall, IfcSlab, IfcDoor, IfcSpace), property sets (Pset_WallCommon, Pset_DoorCommon), and relationships (containment, connection, decomposition).

IFC versions: IFC2x3 is still the most widely deployed (supported by all major BIM tools); IFC4 adds improved geometry kernels, property templates, and infrastructure entities; IFC4.3 extends to rail, road, bridge, and tunnel infrastructure. The buildingSMART alliance maintains the standard and certification program (IFC export/import conformance testing).

Practical considerations: IFC export quality varies wildly between authoring tools — some produce clean, well-classified models while others export geometrically correct but semantically poor data. Use Model View Definitions (MVDs) to specify which data should be included (Coordination View for clash detection, Design Transfer View for full model exchange). IFC files can be validated using tools like Solibri, BIMcollab, or the open-source IfcOpenShell library. For many public-sector projects globally, IFC delivery is now contractually required.

Why It Matters

IFC (Industry Foundation Classes) is the ISO 16739 open, vendor-neutral data model that lets BIM tools exchange building information, making it the cornerstone of openBIM and a requirement in many national BIM mandates.

Best Practices

  • Agree the IFC version (IFC4/IFC2x3) and Model View Definition (MVD) for exchange.
  • Map elements to correct IFC classes and property sets before export.
  • Validate exports with an IFC checker (e.g. Solibri, IfcOpenShell) and IDS.
  • Use IFC for coordination/handover, keeping native files for authoring.

Common Pitfalls

  • Exporting to the wrong IFC version/MVD for the recipient.
  • Mis-classified elements (walls exported as generic proxies).
  • Assuming round-trip IFC editing is lossless.
  • Skipping validation, so bad data reaches partners.

Enterprise Production Implementation & GstarCAD 2027 Workflow

In industrial engineering production, mastering IFC (Industry Foundation Classes) is essential for maintaining strict drawing database hygiene, geometric precision, and cross-disciplinary interoperability across DWG, BIM (IFC 4.3), and mechanical (STEP AP242 / ASME Y14.5) deliverables. When implementing this concept within GstarCAD 2027 Professional, GstarCAD Mechanical, or heterogeneous multi-CAD environments, engineering teams should adhere to the following standardized verification protocol:

  • Database Serialization & Binary Fidelity: Ensure all entities and symbol table records associated with IFC (Industry Foundation Classes) are authored on standardized ISO 13567 layers rather than Layer 0 or Defpoints, and verify lossless round-trip persistence in native DWG (AC1032) format.
Implementation Stage GstarCAD / AutoCAD Execution Quality Assurance (QA/QC) Gate
1. Environment Setup Load corporate .dwt template; verify INSUNITS and LUNITS. Confirm 1:1 metric (mm) or imperial unit consistency across all linked Xrefs.
2. Geometry & Metadata Authoring Apply associative constraints, block attributes, or GD&T tolerance frames. Verify zero disassociated annotations via ANNOMONITOR = 2.
3. Deliverable Exchange Publish via Sheet Set Manager (SSM) or export to DWG / IFC / STEP. Inspect output in DWG FastView or FastView 3D before client release.
